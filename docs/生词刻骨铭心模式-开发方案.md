# 生词"刻骨铭心"模式 —— 可执行开发方案

> 基于《IELTS Vocabulary Training Engine 完整设计文档 v1.0》与现有代码库深度分析

---

## 一、设计文档 vs 现有代码库：架构差异分析

设计文档假设的服务端架构（PostgreSQL + Redis + Spring Boot）与当前应用的**本地优先架构**存在根本差异：

| 维度 | 设计文档假设 | 现有代码库实际 |
|------|------------|--------------|
| 数据存储 | PostgreSQL + Redis | 浏览器 IndexedDB（idb wrapper） |
| 后端 | Spring Boot + REST API | 无状态 Python 服务（仅 ASR/对齐） |
| 状态管理 | 服务端 Session + Redis 缓存 | 客户端 createStore + useSyncExternalStore |
| AI 调用 | 服务端 AI Provider Layer | 客户端 LangChain → /api/* BFF 路由 |
| 用户体系 | users 表 + user_id | 无用户系统（单机本地） |

**结论**：需要将设计文档的核心引擎**适配为客户端实现**，所有训练状态存储在 IndexedDB，AI 内容生成通过现有 BFF 路由调用 LLM。

## 二、功能可行性逐一分析

### 1. 六维能力模型（Semantic / Recognition / Listening / Collocation / Recall / Production）

**可行性：✅ 完全可行**

- 现有 `VocabEntry` 只有 `text`、`context`、`note`、`frequency` 字段，无任何评分维度
- 需要扩展 `types/vocabulary.ts`，新增 `UserWordState` 接口
- 六维分数存储在 IndexedDB，key 格式 `userword:{entryId}` 或直接嵌入 VocabEntry
- **建议**：创建独立的 `UserWordRecord`，通过 `entryId` 关联 `VocabEntry`，保持数据解耦

**改动范围**：`types/vocabulary.ts`（新增类型）、`platform/storage/schema.ts`（新增 key）、`stores/vocab-store.ts`（新增状态读写）

### 2. 用户单词状态机（NEW → LEARNING → REVIEW → MASTERED → RELEARNING）

**可行性：✅ 完全可行**

- 纯状态机逻辑，适合放在 `core/vocab/` 作为纯 TS 模块
- 状态转换条件基于六维分数 + 掌握度，全部可由规则引擎驱动
- 无需服务端参与

**改动范围**：新建 `core/vocab/state-machine.ts`

### 3. 评分引擎（Performance = Accuracy × 0.6 + Speed × 0.2 + Confidence × 0.2）

**可行性：✅ 完全可行**

- 现有 `core/training/scoring.ts` 已有简单评分模式（accuracy-based）
- 新引擎需要增加 SpeedScore（响应时间映射）和 ConfidenceScore（用户自评）
- 纯计算逻辑，零依赖

**改动范围**：新建 `core/vocab/scoring.ts`，或扩展现有 scoring.ts

### 4. 维度分数更新（learningRate × performance × (100 - oldScore)）

**可行性：✅ 完全可行**

- 纯数学计算，Elo 风格渐进更新
- 需要保存每次 attempt 的 `score_before` 和 `score_after` 用于回放
- 设计文档要求算法版本化（scoringVersion），在客户端可通过常量实现

**改动范围**：新建 `core/vocab/dimension-update.ts`

### 5. Mastery Engine（加权总分 + Guardrail）

**可行性：✅ 完全可行**

- 加权公式：`semantic×0.15 + recognition×0.10 + listening×0.20 + collocation×0.15 + recall×0.20 + production×0.20`
- Guardrail：listening≥75, recall≥80, production≥75 才能判 MASTERED
- 纯规则引擎

**改动范围**：新建 `core/vocab/mastery.ts`

### 6. SRS 间隔复习（FSRS 类算法）

**可行性：✅ 可行，但需简化**

- 完整 FSRS 算法有 17 个参数，客户端实现复杂度高
- **V1 建议**：采用简化版 SM-2 变体（stability + difficulty + retrievability 三参数），后续可升级
- 现有 IndexedDB 可存储 `nextReviewAt`、`stability`、`difficulty`、`retrievability`
- 复习队列通过 `nextReviewAt` 筛选当日到期词

**改动范围**：新建 `core/vocab/srs.ts`

### 7. 训练任务引擎（11 种 Task Type）

**可行性：⚠️ 分阶段可行，部分依赖 AI**

| Task Type | 难度 | 可行性 | 依赖 |
|-----------|------|--------|------|
| WORD_TO_MEANING | 1 | ✅ 立即可做 | 需要词义数据（AI 生成或词典 API） |
| MEANING_TO_WORD | 2 | ✅ 立即可做 | 同上 |
| AUDIO_TO_WORD | 2 | ✅ 可行 | 现有 TTS 服务（kokoro-tts / DashScope TTS） |
| AUDIO_TO_MEANING | 2-3 | ✅ 可行 | TTS + 词义数据 |
| CONTEXT_FILL | 2-3 | ⚠️ 需 AI | 需要 LLM 生成填空句 |
| COLLOCATION_MATCH | 2-3 | ⚠️ 需 AI | 需要 LLM 生成搭配数据 |
| COLLOCATION_FILL | 3 | ⚠️ 需 AI | 同上 |
| SYNONYM_DISTINCTION | 3-4 | ⚠️ 需 AI | 需要 LLM 生成近义词辨析 |
| SENTENCE_RECALL | 3-4 | ⚠️ 需 AI | 需要 LLM 生成语义提示 |
| SENTENCE_PRODUCTION | 4 | ⚠️ 需 AI | 需要 LLM 评价用户造句 |
| IELTS_APPLICATION | 5 | ⚠️ 需 AI | 需要 LLM 生成 IELTS 场景 + 评价 |

**V1 MVP 建议**：先实现 5 种基础任务（WORD_TO_MEANING、MEANING_TO_WORD、AUDIO_TO_WORD、CONTEXT_FILL、SENTENCE_PRODUCTION），跑通闭环后再扩展。

### 8. 自适应 Task Selector

**可行性：✅ 可行**

- Priority = Weakness × TaskDimensionWeight × ForgettingRisk × IELTSImportance × Novelty
- 纯客户端计算，基于当前 UserWord 状态
- Exploitation/Exploration 比例（70/15/10/5）通过随机数实现

**改动范围**：新建 `core/vocab/task-selector.ts`

### 9. Training Session Engine（逐题自适应）

**可行性：✅ 可行**

- 现有 `core/training/session.ts` 已有状态机模式（createSession → submit → next）
- 新的 vocab session 需要支持**动态出题**（每题完成后重新计算下一题）
- 与现有 session 模式不同：现有是静态队列，新的是动态生成

**改动范围**：新建 `core/vocab/session.ts`

### 10. AI 内容生成（词义、例句、搭配、联想、IELTS 场景）

**可行性：✅ 可行，复用现有 LLM 基础设施**

- 现有 `lib/llm/` 已有完整的 LangChain + ChatOpenAI 集成
- 支持 DashScope（Qwen）和 MiMo provider
- BFF 路由 `/api/translate` 模式可复用为 `/api/vocab/generate`
- 需要定义结构化 JSON Schema 约束 AI 输出

**改动范围**：新建 `lib/llm/vocab-content-generator.ts`、新建 `app/api/vocab/generate/route.ts`

### 11. AI 造句评价（Production Evaluation）

**可行性：✅ 可行**

- 设计文档定义了结构化 JSON 输出：wordUsage + grammar + collocation + naturalness + ieltsRelevance
- 复用现有 LLM 调用链路，只需更换 prompt
- 超时/失败降级策略：先保存 PENDING_EVALUATION，异步更新

**改动范围**：新建 `lib/llm/vocab-evaluator.ts`、新建 `app/api/vocab/evaluate/route.ts`

### 12. Progressive Fading（渐进减少提示）

**可行性：✅ 可行**

- 根据 attemptCount 和 mastery 分数动态调整提示量
- 纯客户端逻辑，UI 层根据状态渲染不同提示

**改动范围**：集成在 task 渲染逻辑中

### 13. Review Episode（多 Task 聚合 → 一次 SRS 更新）

**可行性：✅ 可行**

- 一个 Episode 包含多个 Task，Episode 结束后聚合评分，触发一次 SRS 更新
- 客户端状态管理，Episode 数据暂存内存，结束后写入 IndexedDB

**改动范围**：集成在 `core/vocab/session.ts` 中

### 14. 数据埋点与延迟回忆统计

**可行性：⚠️ V1 简化**

- 完整的 D+1/D+7/D+30 延迟回忆需要定时任务触发复习提醒
- V1 可以记录 attempt 时间戳，用户下次打开时检查是否有到期复习
- 无服务端 cron job，依赖用户主动打开应用

**改动范围**：`stores/vocab-store.ts` 增加复习队列查询

## 五、关键技术决策

### 5.1 数据存储方案

```typescript
// UserWordRecord —— 存储在 IndexedDB，key = userword:{entryId}
interface UserWordRecord {
  entryId: string              // 关联 VocabEntry.id
  status: 'NEW' | 'LEARNING' | 'REVIEW' | 'MASTERED' | 'RELEARNING'
  dimensions: DimensionScores  // 六维分数
  masteryScore: number         // 掌握度 0-100
  // SRS 参数
  stability: number
  difficulty: number
  retrievability: number
  nextReviewAt: number | null  // 下次复习时间戳
  lastReviewAt: number | null
  // 统计
  attemptCount: number
  correctCount: number
  wrongCount: number
  createdAt: number
  updatedAt: number
}
```

### 5.2 AI 内容生成策略

- **按需生成**：首次训练某词时调用 AI 生成 WordKnowledge，缓存到 IndexedDB
- **批量预生成**：用户可选择"预生成全部"（异步，展示进度）
- **缓存复用**：已生成的内容不重复调用
- **降级策略**：AI 失败时使用基础词义（VocabEntry.definition 或手动输入）

## 六、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| AI 内容生成质量不稳定 | 训练体验差 | 结构化 JSON Schema 约束 + 人工校验 + 缓存复用 |
| AI 调用延迟高 | 训练卡顿 | 预生成 + 加载态 + 客户端缓存 |
| IndexedDB 数据量大 | 性能下降 | 分页加载 + 过期数据清理 |
| SRS 参数未经调优 | 复习间隔不合理 | V1 用保守默认值，后续根据数据调整 |
| 无服务端 → 无延迟回忆提醒 | 复习不及时 | 应用内提醒 + 浏览器 Notification API |
| 词义数据来源 | 准确性 | 优先使用词典 API，AI 生成作为补充 |

---

## 七、与现有训练模式的关系

现有 3 种训练模式（Shadowing / Recitation / ReadAloud）是**句子级别**的口语训练，依赖录音 + ASR/SOE 评分。

新的"刻骨铭心"模式是**单词级别**的记忆训练，不需要录音，核心是认知记忆 + 主动回忆。

两者互补：
- 刻骨铭心模式建立词汇基础（认识、记住、会用）
- 口语训练模式验证真实语境中的使用能力

**不修改现有训练模式**，新增独立的训练入口和页面。
