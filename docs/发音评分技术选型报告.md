> 调研时间：2026-10-11。所有价格与免费额度均为"查询于 2026-10"，以官方定价页 / 官方 API 文档 / GitHub 仓库原文为准；未能核实的条目已标注"待确认"。本报告服务于跟读评分（契约② SOE）的真实服务选型。

## 1. 背景与需求

### 1.1 项目现状

| 项 | 现状 |
|----|------|
| 契约② | `POST /api/v1/soe/evaluate`：入参 16kHz mono WAV + refText；出参 `total / accuracy / fluency / integrity` + `words[{text, score, phonemes[{symbol, score}]}]`（`docs/系统架构设计.md` §3.3） |
| 前端 | mock 评分 `client/services/mock/soe.ts`（确定性伪评分，约 1/7 词 <60 供 ScorePanel 标红验证） |
| 后端 | Fastify 代理已规划（`soe.route.ts` 在架构图中，尚未接真实服务） |
| 已有算力 | WhisperX 对齐服务器（`server/start.sh`，CPU/GPU 可选，wav2vec2 词级对齐） |
| 已有云账号 | 阿里云百炼/DashScope（Qwen TTS + ASR）、腾讯云（文本翻译） |

### 1.2 需求画像

- **场景**：跟读/朗读评分——已知参考文本 + 句子级短音频（约 5 秒），需要句级总分 + 三维度分、词级分数（UI 标红）、音素级反馈（教学价值）。
- **规模**：单用户、低并发、预算敏感的本地优先个人应用（PC Web + Mobile H5）。
- **成本估算口径**：500 句/月 × 5 s = 2,500 s ≈ **41.7 分钟 ≈ 0.69 音频小时/月**。

### 1.3 主流实现原理（一页概览）

发音评分的主流技术是 **GOP（Goodness of Pronunciation）族管线**：G2P 将参考文本转为音素序列 → 声学模型（音素 CTC / 混合模型）输出逐帧音素后验 → 强制对齐定位每个音素的时间段 → 用后验概率比计算音素级 GOP 分 → 聚合成词分/句分，叠加流利度（停顿、语速）、完整度（漏读/增读）、韵律（重音/语调）等维度。商业云服务的差异主要在：声学模型对二语（L2）学习者口音的适配、分数稳定性（与专家打分的相关性）与商业 SLA。

## 2. 云服务 API 调研

### 2.1 Microsoft Azure Speech · Pronunciation Assessment（发音评估）

来源：[官方 How-to 文档](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment)（文档更新 2026-07）、[语言支持](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=pronunciation)、[全球定价页](https://azure.microsoft.com/en-us/pricing/details/cognitive-services/speech-services/)、[Azure 中国定价页](https://www.azure.cn/pricing/details/cognitive-services/)（页面更新 2026-09-07）

**能力**（官方文档原文，查询于 2026-10）：

- **句级维度**：`AccuracyScore`（音素与母语者匹配度，粒度=音节/词/全文）、`FluencyScore`（静音停顿使用是否接近母语者）、`CompletenessScore`（**已发音词数 / 参考文本词数**）、`ProsodyScore`（重音、语调、语速、节奏，需 `EnableProsodyAssessment()` 显式开启）、`PronScore`（四维加权总分，任一维度缺失时不计入）。
- **词级**：每词 `AccuracyScore` + `ErrorType`（`None / Mispronunciation / Omission / Insertion`，Omission/Insertion 需开启 `EnableMiscue`）。
- **音素级**：每个词返回 `Phonemes[{Phoneme, AccuracyScore}]`，支持 `phonemeAlphabet: "IPA"` 或 `"SAPI"`；还有音节分组（Syllable group，en-US）。
- **配置参数**（REST JSON / SDK）：`referenceText`（必须提供参考文本）、`gradingSystem: FivePoint|HundredMark`、`granularity: Word|Phoneme|FullText`、`enableMiscue`。音频超过 30 秒需 continuous 模式，且 continuous 模式不支持 `EnableMiscue`。
- **语言/区域**：支持 33 个 locale（含 `en-US / en-GB / en-AU / en-CA / en-IN / zh-CN` 等），在所有 STT 区域可用；SDK（含 JS）与 REST 均支持。
- **音频**：16kHz mono WAV 直接兼容（项目录音格式零改动）。

**定价**（查询于 2026-10）：

|----|----|----|

| STT 标准实时转写 | 按音频小时计费（官方页动态渲染未抓到数字，长期公开价约 $1/h，**待确认**） | ¥3/小时 |

- **延迟**：5 秒句子实时评测通常亚秒级返回（**待确认**，未实测）。

### 2.2 科大讯飞 · 智能口语评测（ISE，语音评测流式版）

来源：[流式版 API 文档](https://www.xfyun.cn/doc/Ise/IseAPI.html)、[产品页](https://www.xfyun.cn/services/ise)、[FAQ](https://www.xfyun.cn/doc/voiceservice/ise/ise_faq.html)、[会员套餐价格表](https://www.xfyun.cn/doc/member/trial.html)（均查询于 2026-10）

- **协议**：WebSocket `wss://ise-api.xfyun.cn/v2/open-ise`，HMAC-SHA256 鉴权，音频 base64 分帧（40ms/1280B 建议）。普通版已下线，仅流式版。
- **英文评测参数**：`ent=en_vip`；`category` 题型枚举：`read_word / read_sentence / read_chapter / simple_expression / read_choice / topic / retell / picture_talk / oral_translation`（本项目用 `read_sentence`）。
- **评分维度（英文，XML 结果）**：
  - 句/篇层：`total_score / accuracy_score / fluency_score / integrity_score / standard_score`（标准度）；成人句子总分公式 = (0.6×accuracy + 0.3×fluency + 0.1×standard) × integrity/100。
  - **词级**：`total_score` + `dp_message` 错误标记（0 正常 / 16 漏读 / 32 增读 / 64 回读 / 128 替换）。
  - **音节级**：`syll_score`、`serr_msg`、`syll_accent`；**音素级：仅错误标记 dp_message，无数值分**（数值音素分 `phone_score` 仅自由说/rec_paper 题型返回）——与 Azure 的音素数值分存在粒度差异。
  - 辅助：`is_rejected`（乱读拒识）、11 类异常行为检测（唱歌、咳嗽、敲键盘等）。
- **音频**：16k/16bit 单声道 pcm/wav/mp3；会话 ≤5 分钟（建议 ≤3 分钟）；英文单句 ≤100 词。默认 **50 路并发**。
- **价格**（查询于 2026-10）：创建应用后**每日 500 次免费调用**（官方 API 文档原文）；正式套餐：语音评测 20 万次/1 年/¥1,200（会员价 ¥1,056），合 **¥0.006/次**。
- **私有化**：官网未见公开离线版/私有化报价，需商务工单（**待确认**）。
- **评分口径**：FAQ 给出"优"= 86~100 分（4.3~5 分制）等参考区间，并支持按年龄段差异化打分（儿童/成人）。

### 3.2 关键判断：能否基于已有 WhisperX 服务器扩展出发音评分？

- WhisperX 的对齐默认用 wav2vec2 ASR 模型做**字符级** CTC 对齐，README 未暴露逐帧后验，也**不输出任何分数**——它只解决"词在哪个时间点"。
- 扩展路径（自建 GOP，工程判断）：换装音素 CTC 模型（如 `facebook/wav2vec2-lv-60-espeak-cv-ft`）→ refText 经 espeak-ng G2P 得目标音素串 → CTC 后验做强制对齐（torchaudio `forced_align`）→ 逐音素后验比 = GOP 分 → 聚合词分/句分（流利度用词间静音、完整度用对齐命中率可自算）。这条路本质上就是 OpenPronounce 的做法，可以直接参考其实现（MIT）。
- 预期代价：自建 GOP 分数质量显著低于商业服务（OpenPronounce 对照专家总分 ρ≈0.65；商业引擎宣称专家拟合 95%+），需要用 speechocean762 做校准；工程量估 1~2 周（G2P、对齐、聚合、HTTP 封装、标定）。好处：零边际成本、数据不出本机、与 WhisperX 服务器共存（CPU int8 可跑，~1.2GB 模型常驻内存）。

---

## 4. 浏览器端方案

- **可行性已具备**：[onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX](https://huggingface.co/onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX)（Apache-2.0）是官方音素识别模型的 ONNX 导出，可用 transformers.js（ONNX Runtime Web）直接 `pipeline('automatic-speech-recognition', ...)` 加载，输入 16kHz，输出 IPA 音素序列（查询于 2026-10）。字符级模型如 [Xenova/wav2vec2-base-960h](https://huggingface.co/Xenova/wav2vec2-base-960h) 也早已在浏览器跑通 ASR。
- **但"浏览器 GOP 评分"没有现成开源实现**：OpenPronounce、ai-pronunciation-trainer 均为 Python 服务端；浏览器端还需自拼 espeak-ng 替代品（JS 端 G2P 词典）、CTC 后验提取、强制对齐与打分聚合。
- **移动 H5 现实约束**：wav2vec2-large fp32 ~1.2GB，量化后仍有数百 MB（具体体积待确认），H5 首屏/流量不可接受；WASM 推理 5 秒音频需数秒级延迟（待实测）；WebGPU 可加速但低端机覆盖差。
- **结论**：技术可行、工程与体验不划算。**不推荐作为主链路**；若未来做"完全离线评分"可作为实验分支（PC Web + 模型缓存 + WebGPU）。

## 5. 选型推荐

### 5.1 推荐方案：Azure Pronunciation Assessment（经 Fastify 代理）

**理由**：

1. **维度与契约②一一对应**：`PronScore→total`、`AccuracyScore→accuracy`、`FluencyScore→fluency`、`CompletenessScore→integrity`；词级分数+ErrorType、音素级数值分+IPA 符号全部原生提供，是五家里唯一"零妥协"满足契约②的（讯飞英文朗读题型音素级只有错误标记）。
2. **成本近零**：月 0.69 小时，F0 免费层（STT 5h/月）下仅 PA 附加功能小额计费（全球区 ≈$0.21/月；中国区 ≈¥2.5/月）。
3. **代理改造成本最低**：REST 单次短音频接口（<15s 音频直接 POST WAV），Fastify 侧一个路由 + 一个字段映射函数即可，无 WebSocket 状态机（讯飞、腾讯都是流式两段式协议，代理实现更重）。
4. **质量与文档**：33 locale（en-US/en-GB 可选口音模型）、JS SDK 也有（但浏览器直连会暴露密钥，必须走代理）、文档/示例最完善。
5. **风险**：个人国内网络访问全球区端点可能不稳——备选路径见 5.2；Azure 中国区可用但需世纪互联订阅与备案主体，个人一般不具备（走全球区 + 代理即可）。

### 5.2 备选方案

| 优先级 | 方案 | 适用条件 | 取舍 |
|---|---|---|---|
| 备选 1 | **腾讯 SOE 基础版**（后付费或 ¥9.9/1 万次包） | Azure 网络不可达时 | 国内直连稳定、已有腾讯云账号、¥2.5/月；**但基础版已宣布停止迭代**（迁移 OEN 的成本与 OEN 定价待确认），句子模式字段映射需核对；两段式协议（初始化+分片）代理实现比 Azure 重 |
| 备选 2 | **讯飞 ISE**（`read_sentence`） | 需要每日免费额度、或将来做多题型（topic/retell 等口语考试题型） | 500 次/日免费最慷慨、题型最全；但 WebSocket 鉴权+分帧协议工程量最大，且英文朗读题型音素级只有错误标记无数值分，契约②的 `phonemes[].score` 需降级 |
| 备选 3 | **自建 GOP（OpenPronounce 路线）挂 WhisperX 服务器** | 完全离线/隐私/零 API 成本的长期方向 | MIT 可商用、CPU 可跑；分数质量最低（ρ≈0.65）、需 1~2 周工程与校准；建议作为 v2 实验而非首发 |
| 不推荐 | 阿里 ssecp / 百度 / 浏览器端 | — | 阿里能力对口但单价未公开且偏 K12 教育定位；百度无公开服务；浏览器端模型体积不适合 H5 |

### 5.3 推荐架构

```
浏览器录音(16k mono WAV, 已有) → Fastify POST /api/v1/soe/evaluate（已有规划）
  → soe.route.ts: multipart 解析 refText + audio
  → providers/azure-soe.ts: Azure STT REST /recognize (language=en-US)
      + Pronunciation-Assessment 头 (referenceText / HundredMark / Phoneme / IPA)
      16k mono WAV 原样透传（Content-Type: audio/wav; codec=audio/pcm; 16k; mono）
  → soe-mapper.ts: NBest → 契约②字段
  → 失败/超时 → 降级 mock（保留现有 failRate 降级路径语义）
```

密钥仅存服务端 env（`SOE_PROVIDER=azure|tencent|mock`、`AZURE_SPEECH_KEY/REGION`）。

## 6. 集成改造清单

### 6.1 后端（server/，Fastify 代理）

1. 新建 `providers/azure-soe.ts`：调用 Azure STT REST 短音频接口，`Pronunciation-Assessment` 头携带 JSON（base64）：`{referenceText, gradingSystem:"HundredMark", granularity:"Phoneme", phonemeAlphabet:"IPA"}`，`enableMiscue:true` 以获得漏读/增读标记（音频 <30s，非 continuous 模式，符合本项目 5s 句子）。REST 头的具体编码细节以 [REST API 文档](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-speech-to-text) 为准（待接入时核对）。
2. 新建 `soe-mapper.ts` 字段映射：

| 契约② | Azure PA 来源 |
|---|---|
| `total` | `NBest[0].PronScore` |
| `accuracy` | `NBest[0].AccuracyScore` |
| `fluency` | `NBest[0].FluencyScore` |
| `integrity` | `NBest[0].CompletenessScore`（已发音词/参考词比值） |
| `words[].text` | `Word` |
| `words[].score` | 词级 `AccuracyScore` |
| `words[].phonemes[].symbol` | `Phoneme`（IPA） |
| `words[].phonemes[].score` | 音素 `AccuracyScore` |
| （新增，见 §7）`words[].errorType` | `ErrorType`（None/Mispronunciation/Omission/Insertion） |

3. `soe.route.ts`：multipart（或 raw body）接收，透传 WAV，统一错误 → 现有 `ApiError('SOE_UPSTREAM_ERROR')` 语义；加超时（建议 10s）与重试 1 次。
4. env/config：`SOE_PROVIDER` 开关，保留 mock provider 以便测试与降级。

### 6.2 前端（client/）

1. `services/` 新增 `SoeRealService`（fetch `/api/v1/soe/evaluate`，multipart：refText + wav Blob），在 `services/index.ts` 工厂按 `NEXT_PUBLIC_SERVICE_MODE` 切换 real/mock（架构既定模式）。
2. `types/`：`SoeEvaluateResponse` 按第 7 节微调（新增 optional 字段，不破坏 mock）。
3. `read-aloud.tsx` / ScorePanel：词级标红继续用 `<60` 阈值，可选叠加 `errorType`（Omission/Insertion 用不同视觉）；音素符号渲染需支持 IPA 字符。
4. `services/mock/soe.ts` 保留不动（测试基准 + 降级路径）。

### 6.3 不需要动的部分

录音链路（16kHz mono WAV 目标格式恰好是所有候选服务的原生输入）；材料/字幕/训练流程；IndexedDB 存储契约。

## 7. 契约②调整建议

主流云服务的维度/粒度与契约②基本对应，但有三处建议微调（保持向后兼容，全部为新增 optional 字段）：

1. **`integrity` 语义澄清**：Azure/讯飞/腾讯对应维度均叫 Completeness（完整度）= 已发音词/参考词比值，契约②的 `integrity` 实为同一概念，建议在 `系统架构设计.md` §3.3 加一行注释说明映射 `CompletenessScore`，字段名可保留。
2. **`words[].errorType`（新增 optional）**：漏读/增读/误读类型是云服务共同输出的强信号（Azure `ErrorType`、讯飞 `dp_message` 0/16/32/64/128），mock 的"约 1/7 词 <60"标红规则可由真实 errorType 替代或并存。
3. **`phonemes[].symbol` 统一为 IPA**：Azure `phonemeAlphabet=IPA`、开源音素模型（espeak）也输出 IPA；建议明确 symbol 字符集为 IPA，避免 SAPI/拼音式符号混入。
4. **`prosody`（新增 optional，默认不返回）**：Azure 独有（prosody 是其计费附加项），暂不启用，字段预留。
5. **参考文本为必填**：四家可用服务均需 refText（无免费说场景），契约②现有定义已满足，无需改动。
