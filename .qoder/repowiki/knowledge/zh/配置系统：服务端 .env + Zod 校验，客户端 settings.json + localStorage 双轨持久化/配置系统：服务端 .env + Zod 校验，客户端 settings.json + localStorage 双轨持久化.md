## 1. 总体方案

仓库采用**前后端分离的双轨配置体系**：

- **后端（server/）**：基于 Node.js Fastify 服务，通过自实现的极简 `.env` 解析器加载环境变量，再用 `zod` 做类型与值域校验，启动时强制校验所选 SOE provider 的凭据是否齐备。
- **前端（client/）**：运行时偏好（播放倍速、循环次数、翻译开关等）走 `platform/storage/prefs.ts` → `localStorage`（键以 `ping-english:` 前缀）；应用级设置（LLM 多模型、SOE 代理、Kokoro TTS、本地 Whisper 服务地址）持久化到用户目录下的 `~/.ping-eng/settings.json`。

## 2. 关键文件

| 模块 | 文件 | 职责 |
|---|---|---|
| server | `src/config/env.ts` | 环境变量 schema、`.env` 解析、provider 凭据校验 |
| server | `.env.example` | 全量可配环境变量模板 |
| client | `lib/server-settings.ts` | `settings.json` 读写（LLM 多模型 / SOE / Kokoro / Local Services） |
| client | `lib/service-endpoints.ts` | 各 provider 默认 endpoint、默认模型、默认音色集中定义 |
| client | `lib/pref-keys.ts` | UI 偏好项键名与取值约定（rate / loop / trainingScope / translateEnabled） |
| client | `platform/storage/prefs.ts` | localStorage 封装（`ping-english:` 命名空间） |

## 3. 架构与约定

### 3.1 后端 env 加载链

`loadEnv()` 的执行顺序为：

1. `loadDotEnv()`：从 `server/.env` 逐行解析 `KEY=VALUE`，跳过空行和 `#` 注释，**不展开变量引用**；若同名 key 已存在于 `process.env`（容器/CI 注入），则直接跳过——即**进程环境变量优先于 `.env` 文件**。
2. `zod.safeParse(process.env)` 用 `envSchema` 校验并赋默认值（如 `PORT=8788`、`HOST='0.0.0.0'`、`CORS_ORIGIN='http://localhost:3000'`、`SOE_PROVIDER='mock'`、`IFLYTEK_FRAME_INTERVAL_MS=40`、`SOE_TIMEOUT_MS=10_000`、`SOE_RETRY=1`）。
3. 跨字段约束校验：根据 `SOE_PROVIDER` 调用 `azureCredsOk` / `tencentCredsOk` / `iflytekCredsOk` 检查密钥齐全性；缺失时抛出带中文提示的 `Error`。
4. 额外格式校验：`AZURE_SPEECH_HOST` 必须以 `http(s)://` 开头。

Provider 选择是枚举型：`mock | azure | tencent | iflytek`，默认 `mock`。文档注释明确“零依赖读 .env”，未引入 `dotenv` 等第三方库。

### 3.2 前端 settings.json

路径固定为 `join(homedir(), '.ping-eng', 'settings.json')`。结构分层：

- `llm`：遗留单模型配置（向后兼容），包含 `baseUrl`、`apiKey`、`asrModel`、`asrEndpoint`、`ttsModel`、`ttsEndpoint`、`translateModel`、`translateEndpoint`、`mnemonicModel`、`mnemonicEndpoint`、`whisperAlignUrl`、`whisperTranscribeUrl`。
- `llmConfigs`：多模型数组，每项含 `id`、`name`、以及上述所有字段；`defaultLlmConfigId` 标记当前默认。
- `localServices`：本地 Whisper 对齐/转写服务 URL。
- `kokoro`：Kokoro TTS 的 `modelId` 与 `modelPath`（默认 `onnx-community/Kokoro-82M-v1.0-ONNX`，模型目录 `~/.ping-eng/kokoro-models`）。
- `soe`：SOE 语音评测配置（`provider` + `proxyUrl` + 各 provider 专属密钥块）。

迁移策略：首次读取 `llmConfigs` 时，若数组为空但存在旧 `llm` 对象，自动将其提升为第一条 `llmConfigs` 并写入 `defaultLlmConfigId`；新增第一个配置或设为默认时，同步回写 `llm` 以保持旧消费者可用。

### 3.3 前端 localStorage 偏好

键名统一以 `pref:` 前缀（实际存储时由 `prefs.ts` 加 `ping-english:` 命名空间）。受控枚举值：

- `pref:rate`：`0.75 | 1 | 1.25`，默认 `1`。
- `pref:loop`：`0 | 1 | 3 | 'inf'`，默认 `0`。
- `pref:trainingScope`：`'all' | 'favorites'`，默认 `'all'`。
- `pref:translateEnabled`：`boolean`，默认 `false`。

### 3.4 服务端点集中管理

`service-endpoints.ts` 是唯一允许维护 endpoint 常量与默认模型/音色的地方，遵循三条设计原则（见文件头注释）：

1. 代码中不得硬编码任何 `baseUrl` 或 endpoint 路径。
2. 所有 URL = `buildServiceUrl(baseUrl, endpoint)`。
3. 缺省 endpoint 由 `getDefaultEndpoint(provider, service)` 提供。

支持的 provider：`dashscope`、`qwen`（作为 dashscope 别名）、`mimo`、`local`；支持的服务种类：`tts`、`asr`、`translate`、`mnemonic`。未知 provider 回退到 `mimo`（OpenAI-compatible）默认值。

## 4. 约定与约束

- **后端环境变量优先级**：进程环境变量 > `.env` 文件（`loadDotEnv` 中 `if (key in process.env) continue` 强制实现）。
- **后端启动失败条件**：当 `SOE_PROVIDER` 指向非 mock 且对应凭据不全时，`loadEnv()` 抛错阻止启动（`env.ts` 第 96–108 行）。
- **Azure HOST 格式**：必须匹配 `/^https?:\/\//`，否则抛错（`env.ts` 第 111–113 行）。
- **前端 LLM 配置迁移**：旧 `llm` 字段在首次访问 `readLlmConfigs` 时自动提升为 `llmConfigs[0]` 并写入 `defaultLlmConfigId`（`server-settings.ts` 第 133–155 行）。
- **前端偏好键名**：所有偏好项键名以 `pref:` 前缀，并通过 `pref-keys.ts` 暴露 getter/setter，禁止业务代码直接使用裸字符串键（`pref-keys.ts` 注释说明“P10 设置页读写、P2 播放器读取默认值”）。
- **前端 baseUrl 禁止硬编码**：`service-endpoints.ts` 文件头注释明确“代码中不得硬编码任何 baseUrl 或 endpoint 路径”。
- **SOE provider 枚举**：仅允许 `mock | azure | tencent | iflytek`（`env.ts` zod enum 与 `server-settings.ts` SoeSettingsConfig 类型双重约束）。
- **settings.json 位置**：固定为用户主目录下的 `~/.ping-eng/settings.json`，目录不存在时 `mkdir({ recursive: true })` 自动创建（`server-settings.ts` 第 52–70 行）。
- **Kokoro 模型目录**：首次读取 `readKokoroSettings` 时若 `kokoro` 段缺失，会写入默认值并 `mkdir(modelPath, { recursive: true })` 确保目录存在（`server-settings.ts` 第 284–291 行）。

## 5. 适用范围

本配置系统覆盖后端运行期配置（端口、CORS、SOE provider 及三厂商凭据、超时重试）与前端用户配置（LLM 多模型、SOE 代理、Kokoro 本地 TTS、Whisper 本地服务、UI 偏好）。仓库未使用 YAML/TOML/JSON Schema 等外部配置格式，也未引入第三方配置库（后端仅用 `zod`，前端纯手写 JSON 读写）。
