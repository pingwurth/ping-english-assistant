## 1. 整体方案

仓库是一个**多模块工作区**，包含三个独立的 Node.js/TypeScript 子项目（`client/`、`server/`、`page-prototype/`）以及两个 Python 服务脚本（`server/align_server.py`、`server/transcribe_server.py`）。没有顶层 `Makefile`、`Dockerfile`、`docker-compose.yml` 或 `.github/workflows`；也没有统一的包管理器 workspace 配置。每个子模块各自管理自己的依赖和构建。

- **前端（client）**：Next.js 16 + React 19，通过 `pnpm` 管理依赖，构建入口为 `next build`。
- **后端（server）**：Fastify 5 + TypeScript，通过 `tsx` 直接运行源码（无预编译产物），测试使用 Vitest。
- **Python 服务**：WhisperX 对齐服务与 faster-whisper 转写服务，由 `server/start.sh` 统一编排。
- **原型（page-prototype）**：独立 Next.js 站点，与主前端解耦。

## 2. 关键文件

- `client/package.json` — 定义 `dev` / `build` / `start` / `test` 脚本，锁定 `next@16.3.0`、`react@^19`、`typescript@5.7.3`、`vitest@^4.1.11`；通过 `pnpm.overrides` 强制 `hono@4.12.25`，并通过 `onlyBuiltDependencies` / `ignoredBuiltDependencies` 控制原生模块安装。
- `server/package.json` — 声明 `engines.node >= 20`，开发/生产均通过 `tsx` 直接运行 TS 源码（`tsx watch src/index.ts` / `tsx src/index.ts`），类型检查 `tsc --noEmit`，测试 `vitest run`。
- `server/start.sh` — 唯一的多语言启动编排脚本，负责 Python venv 创建、依赖安装、NLTK punkt_tab 下载、ffmpeg 检测、Node/pnpm 校验，并按 `--server` 参数启动 align / transcribe / both / soe / all 五种模式。
- `client/vitest.config.mts` / `server/vitest.config.mts` — 分别限定测试范围为 `core/**/*.test.ts, services/**/*.test.ts` 与 `src/**/*.test.ts`，环境均为 `node`，明确不跑浏览器/React 测试。
- `server/.env.example` — SOE 代理的环境变量模板。
- `client/next.config.mjs` / `postcss.config.mjs` / `tsconfig.json` — Next.js 构建与样式管线。

## 3. 架构与约定

### 3.1 依赖与版本策略

- 所有 JS/TS 子模块都使用 `pnpm`（`pnpm-lock.yaml` 存在），但**没有顶层 pnpm workspace**，每个模块独立 `pnpm install`。
- 依赖版本以 `package.json` 中的语义化范围为主（如 `^4.1.11`），仅对关键库做精确锁定（`next@16.3.0`、`hono@4.12.25` via overrides）。
- Python 依赖集中在 `server/requirements.txt`，由 `start.sh` 在首次运行时通过 `pip install -r requirements.txt` 安装到 `.venv`。

### 3.2 构建与运行

- **client**：`pnpm dev` → `next dev`；`pnpm build` → `next build`；`pnpm start` → `next start`。
- **server**：`pnpm dev` → `tsx watch src/index.ts`（热重载）；`pnpm start` → `tsx src/index.ts`；`pnpm check` → `tsc --noEmit`；`pnpm test` → `vitest run`。
- **Python 服务**：通过 `./server/start.sh --server {align|transcribe|both|soe|all}` 统一启动，额外参数（如 `--device cuda --compute-type float16`）透传给 Python 进程。
- `start.sh` 内部逻辑：
  - 解析 `--server` 参数并校验取值（`align|transcribe|both|soe|all`，否则 exit 1）。
  - 根据模式决定是否需要 Python / Node。
  - Python 路径：检查 `python3` → 创建/激活 `.venv` → 按需安装 `whisperx`、`fastapi`、`uvicorn`、`faster_whisper` → 下载 NLTK `punkt_tab`（优先 nltk downloader，失败则从 GitHub raw 下载 zip 解压到 `$HOME/nltk_data/tokenizers/punkt_tab`）→ 警告缺失 `ffmpeg`。
  - Node 路径：检查 `node` / `pnpm` → 校验 `process.versions.node` major ≥ 20 → 若 `node_modules` 不存在则执行 `pnpm install`。
  - 启动阶段：align 后台进程监听 8765，transcribe 前台监听 8766，SOE 代理监听 8788；`both`/`all` 模式用 `sleep 1` 等待端口绑定后拉起下一个进程。

### 3.3 测试

- 前后端共用 Vitest 4.x，测试目录约定：`__tests__/` 下按被测模块组织，根级 `*.test.ts` 也可被 include。
- client 测试仅覆盖纯 TS 逻辑（`core/`、`services/mock/`），不包含 UI/React 组件测试。
- server 测试覆盖 routes、providers、auth、mapper、wav-pcm 等后端逻辑。

### 3.4 未发现的机制

- 仓库中**不存在** `Makefile`、`Dockerfile`、`docker-compose.*`、`.github/workflows/*`、CI 流水线、发布脚本或版本号集中管理文件。搜索匹配项全部来自 `.claude/skills/code-review-p` 等第三方 skill 的引用文本，并非本项目自身配置。
- 没有跨平台交叉编译目标；Python 服务依赖系统级 `ffmpeg`，Node 服务要求 Node ≥ 20。

## 4. 约定与约束

- **规则（由代码强制）**：`server/start.sh` 对 `--server` 参数做白名单校验，非法值直接 `exit 1`；Python 模式下缺少 `python3` 或 `ffmpeg` 会报错/告警；Node 模式下要求 Node ≥ 20 且必须安装 `pnpm`，否则退出。
- **规则（由 package.json 强制）**：server 模块通过 `engines.node >= 20` 声明最低 Node 版本；client 通过 `pnpm.overrides.hono = "4.12.25"` 强制 hono 版本。
- **约定（观察到的模式）**：每个子模块独立维护 `package.json` + `pnpm-lock.yaml`；测试统一使用 Vitest 并在 `vitest.config.mts` 中显式设置 `environment: 'node'`；Python 依赖通过 `start.sh` 懒加载而非预先安装。
- **约束（文档层面）**：client 的 vitest 注释写明“不配置浏览器/React 测试（原型阶段约束）”，表明当前测试范围是有意收窄的。
