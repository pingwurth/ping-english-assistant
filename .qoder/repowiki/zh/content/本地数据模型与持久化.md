# 本地数据模型与持久化

> 本地优先：所有用户数据在浏览器 IndexedDB，后端无库无状态。LLM/SOE 配置例外，落在本机文件 `~/.ping-eng/settings.json`。

## 1. 三个 object store

`platform/storage/idb.ts` 是**手写 Promise 封装，DB 名 `ping-english-assistant`，`DB_VERSION = 2`，零运行时依赖（没有引 `idb` 库）**。根 `AGENTS.md` 与 `docs/系统架构设计.md` §4.2 早期都误写成「`idb` 封装」，已于 2026-11-02 校准为「手写 Promise 封装」。

| store | 内容 | key |
|-------|------|-----|
| `materials` | `MaterialRecord = { material, subtitleData }` | `materialId` |
| `blobs` | 媒体文件 Blob | `materialId` |
| `records` | 进度 / 收藏 / 笔记 / 训练记录 / 生词本 / 词条 / 助记 / 材料集 | 类型前缀 + 业务 id |

每个 store 暴露最小 KV API：`get / put / delete / allKeys / clear`（`KvStore` 接口）。`mediaRef` / `subtitle.ref` 的写法是 `idb://blobs/{id}`、`idb://materials/{id}` 这类引用串，真实数据按 key 取。

**降级策略是这套设计的核心**：`useMemory` 在没有 `indexedDB`（SSR）、打开失败、`onblocked`（其他标签页持旧连接）或任一事务抛错时置真，之后**永久**走内存 `Map` 兜底，调用方永不因存储层崩溃——代价是数据不再落盘且无任何异常提示。`isMemoryFallback()` 供 UI 提示，`estimateUsage()` 走 `navigator.storage.estimate()`，不可用时返回 0。

## 2. key 前缀约定（`platform/storage/schema.ts` 的 `RECORD_KEYS`）

```
progress:{materialId}
fav:{materialId}:{sentenceIndex}
note:{materialId}:{sentenceIndex}
train:{recordId}
vocabbook:{bookId}
vocabentry:{entryId}
mnemonic:{entryId}
collection:{collectionId}
```

`records` 是共享 store，靠 key 前缀区分业务，因此**前缀匹配删除极易误伤**。`removeMaterial()` 里就有明确防护：`progress:` 必须精确等值匹配（用前缀匹配会把 `m-1` 和 `m-10` 一起删掉），`fav:`/`note:` 用 `fav:${id}:` 带冒号前缀，`train:` 则必须逐条读出再比对 `materialId`。写新的级联删除时照抄这套口径。

## 3. 字幕解析结果内联存储

`MaterialRecord.subtitleData` 直接存**解析后的 `SubtitleData` JSON**，而不是只存字幕文件引用——目的是避免每次启动重复解析（架构 §4.2 的落地）。无字幕材料为 `null`。

## 4. 核心业务模型（`types/`）

- `Material`：`mediaType('video'|'audio')`、`mediaRef`（H5 为 IndexedDB Blob key）、`mediaFileName`、`mediaSizeBytes`、`subtitle{ref,format,isBilingual,sentenceCount}|null`、`durationMs`、`createdAt`、`lastOpenedAt`、`collectionId?: string|null`。**展示型字段（颜色/进度/最后学习）不进模型，由组件按 id 派生**。
- `MaterialCollection`：扁平不嵌套；删除集合只把成员 `collectionId` 置 `null`，材料本身保留。
- `LearningProgress`：`lastPositionMs` + `playedSentenceIndexes[]`（驱动材料库进度条）。
- `TrainingRecord`：`mode` 五值联合 + `scope('all'|'favorites')` + 归一化 `score(0-100)` + `detail`（`PuzzleDetail | DictationDetail | ReadAloudDetail | ReportDetail`）。
- `VocabBook` / `VocabEntry`：词条记录 `text`、所在句 `context`、来源 `materialId + sentenceIndex`、`frequency`（材料导入时累加）、可选 `definition`（LLM 释义）与 `note`；`DEFAULT_BOOK_ID = 'default'`，首次初始化自动创建。
- `MnemonicCard`（`types/mnemonic.ts`）：与 LLM 返回 JSON 一一对应 —— `core_meaning`、`phonetic_mnemonic`、`word_roots`、`examples[]`、`collocations[]`。字段用 snake_case 是为了和模型输出对齐，不要改成 camelCase。

## 5. store 层的读写模式

`material-store.ts` 是样板：`createStore({ ready, records, collections })` → 异步函数操作 IDB → `refresh()` 全量重读并广播。

- `initMaterials()` 幂等（`initPromise ??=`），先 `seedIfEmpty()` 再 `refresh()`。
- 排序 `sortByRecent()`：`lastOpenedAt` 降序，从未学习（0）排后并按 `createdAt` 降序。
- `touchMaterial(id)` 打开材料时更新 `lastOpenedAt`。
- `assignMaterialCollection()` 有**陈旧 ID 防护**：目标集合若已被其他标签页删除则静默不写。
- 媒体 Blob 三个入口 `putMediaBlob / getMediaBlob / deleteMediaBlob`，删除材料时级联清理孤儿 Blob。
- 训练范围偏好走 `localStorage`（`lib/pref-keys.ts` + `platform/storage/prefs.ts` 的 `getPref/setPref/hasPref/exportAllPrefs`，键形如 `prefs:pref:trainingScope`），不进 IndexedDB。

## 6. 种子数据

`data/seed.ts` 提供 `seedMaterials`（`mock-001` / `ted` / `bbc` / `movie` 四条，`mediaRef` 为 `seed://...`）+ `seedSentences`（同一组 5 句被四条材料共用），首次启动（`materials` store 为空）自动注入，`buildSeedSubtitle()` 把种子句子内联成 `SubtitleData`。调试"数据莫名变多/被重置"时先确认是否走了种子注入分支；清空浏览器 IndexedDB 会重新触发。

## 7. 备份/导出

`core/backup/backup-format.ts`（`BACKUP_APP_ID`、`BACKUP_FORMAT_VERSION`、`parseBackupJson`、`planImport`、媒体 manifest）+ `core/backup/zip.ts`（纯 TS zip 读写，依赖 `fflate`；`createZipWriter/indexZip/readEntry/isZipMagic`）负责数据打包，`platform/storage/backup.ts` 做浏览器侧落盘与选择器（`buildBackup/buildFullBackupZip/importBackup/importZipBackup/prepareZipImport`）。设置页（`pages/settings.tsx`）串起 JSON 与 zip 两条导出/导入路径。
