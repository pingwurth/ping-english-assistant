## 字幕解析器（core_subtitle）

<!-- 迁入：kind=module, slug=core_subtitle, name=字幕解析器 -->

### overview

SRT/LRC 字幕解析与双语拆分，输出句子级 `SubtitleData`。零依赖纯 TS，是播放控制与所有训练模式的共同数据源（架构 ADR-2）。

### architecture_design

```
timestamp.ts  parseSrtTimestamp / parseLrcTimestamp / formatSrtTimestamp
srt.ts        parseSrt(text) → RawBlock[]
lrc.ts        parseLrc(text) → RawBlock[]
bilingual.ts  isCJK / stripWordPunctuation / splitWords / splitBilingual / detectBilingual
errors.ts     SubtitleParseError（带行号）
index.ts      parseSubtitle(text, format?, knownDurationMs?) → SubtitleData
              exportSrt(sentences) → string
```

`index.ts` 是唯一对外入口，页面/存储层只用 `parseSubtitle` 与 `exportSrt`。

### coding_conventions

- 双语判定顺序固定：两行上英下中 → `textEn/textZh`；上中下英 → 反序；单行 → 仅 `textEn`；两行同类或多行 → 按语言分组合并。
- 合并多行用 `'\n'` 连接（**保留原文断行，导出 SRT 可原样回写**），渲染侧配 `whitespace-pre-line`，下游切词一律 `/\s+/`。
- `isCJK` 字符类覆盖 `\u2E80-\u9FFF`、假名、谚文扩展区，改正则要同步测 `__tests__/`。
- `detectBilingual` 阈值 30%：含 `textZh` 句占比 >0.3 才判双语。

### gotchas_and_constraints

- 解析失败必须抛带行号的 `SubtitleParseError`，导入页依赖它做就地提示，不得降级为静默忽略。
- LRC 无结束时间：`endMs` 取下一句 `startMs`，末句取 `totalDurationMs`（故 `parseSubtitle` 需要 `knownDurationMs` 才能给末句收尾）。
- `stripWordPunctuation` 保留撇号（`don't` 是一个词），去掉会导致九宫格拼词错位。

## 训练引擎（core_training）

<!-- 迁入：kind=module, slug=core_training, name=训练引擎 -->

### overview

听写差分、九宫格拼句、会话状态机、小结加工四块纯 TS 逻辑，服务于五种训练模式（puzzle/dictation/read-aloud/shadowing/recitation）。

### architecture_design

| 文件 | 对外能力 |
|------|----------|
| `session.ts` | `createSession(mode, sentences, scope)`、`submit/next/hint/skip/currentSentence/makeRecordId`、`sentencesInScope()`；`SessionState{queue,cursor,status,results,hintCount,attemptCount,startedAt}` |
| `dictation-diff.ts` | `normalize`、`toWords`、`diffWords`（逐词 LCS → `DiffToken{type: correct\|wrong\|missing\|extra}`）、`sentenceAccuracy` |
| `puzzle.ts` | 线性拼句 `buildTiles/checkAnswer/nextHint/puzzleScore`；九宫格 `GRID_SIZE=9` + `initGridState/selectGridWord/getGridHint/gridScore/collectDistractorWords/splitTargets/isSameWord` |
| `scoring.ts` | `summarize(results, durationMs) → SessionSummary`、`formatElapsed()` |
| `index.ts` | 聚合导出 |

事件迁移全部返回新状态对象（不可变），与 UI 框架无关。

### design_rationale

- 范围过滤（全文 / 收藏句）集中在 `sentencesInScope()`，逐句模式共用同一口径，避免各页实现漂移。
- 听写评分用 LCS 逐词 diff 而非编辑距离：需要 `missing/extra` 两类语义给 UI 分别着色。
- `scoring.ts` 只做**小结**（正确率句均、最弱句 TOP3、总播放数），不做 SOE 分数加工 —— 架构文档 §2.5 把它标为"评分加工"已偏移，SOE 厂商字段归一在 `server/src/services/soe/soe-mapper.ts`。

### coding_conventions

- 纯函数，不 import React/DOM/IndexedDB，否则 `pnpm test`（node env）直接挂。
- 新增训练模式要同时扩 `types/training.ts` 的 `TrainingMode` 与 `TrainingRecord.detail` 联合。
- 单测共置 `core/training/__tests__/*.test.ts`，已有 `dictation-diff` / `puzzle` / `puzzle-grid` / `session` 四组。

### gotchas_and_constraints

- `puzzle.ts` 两套实现并存（线性 vs 九宫格），改逻辑前先确认调用页。
- `summarize()` 的 `weakest` 只收未全对句且最多 3 条，按正确率升序。

## 播放器与音频抽象（core_player_audio）

<!-- 迁入：kind=module, slug=core_player_audio, name=播放器与音频抽象 -->

### overview

`core/player` 定义平台无关播放器契约与逐句控制，`core/audio` 产出 ASR/SOE 统一的目标音频格式。

### api_contract

- `PlayerController`：`load(MediaSource)` / `play` / `pause` / `seekTo(ms)` / `setRate(0.5~2.0)` / `setVolume(0~1)` / `setLoop(startMs,endMs)` / `clearLoop` / `getCurrentTimeMs` / `getDurationMs` / `getState` / `on|off(PlayerEvents)` / `destroy`。
- `PlayerEvents`：`timeupdate(currentMs)`、`statechange(PlayerState)`、`ended`、`error(PlayerError)`；`PlayerState = idle|loading|ready|playing|paused|ended|error`。
- `SentencePlayer`：`playSentence(i)` / `next` / `prev` / `loopSentence` / `locateSentence(ms)`（二分）/ `onSentenceChange`；常量 `LOOP_TOLERANCE_MS = 120`。
- `core/audio/wav-encoder.ts`：`TARGET_SAMPLE_RATE = 16000`、`encodeWav(Float32Array, sampleRate?) → Blob`、`wavDurationMs(sampleCount, sampleRate?)`、`WAV_MIME`。

### design_rationale

接口形状沿用架构 ADR-1（为多端预留），但当前仅 `platform/html-player.ts` 一个浏览器实现；`index.ts` 只做类型再导出。16kHz mono 是 ADR-5 落地，换取"一份录音同时喂 ASR 与 SOE、后端免转码"。

### gotchas_and_constraints

- `locateSentence` 依赖句子按 `startMs` 升序，字幕编辑后须保证有序。
- 上层只订阅 `onSentenceChange`，不要直接订阅 `timeupdate` 做 setState（高频重渲染）。

## 浏览器适配层（platform_browser）

<!-- 迁入：kind=module, slug=platform_browser, name=浏览器适配层 -->

### overview

唯一允许访问浏览器 API 的一层：HTML 媒体元素控制、麦克风录音、Kokoro TTS Worker、IndexedDB/localStorage/备份。

### architecture_design

```
platform/html-player.ts        HtmlPlayerController + createHtmlPlayer(kind, element?)
platform/recorder.ts           WebRecorder + createRecorder()；RecorderError/PermissionError/NotStartedError
platform/kokoro-tts.ts         主线程门面：KOKORO_VOICES、preloadKokoroModel、set/getKokoroModelId、
                               generateKokoroTts、subscribeKokoroLoad
platform/kokoro-worker.ts      Worker 内实际推理（kokoro-js + @huggingface/transformers, ONNX）
platform/kokoro-protocol.ts    主线程 ↔ worker 消息协议与加载阶段类型
platform/storage/{idb,schema,prefs,backup}.ts
```

### tech_stack

`kokoro-js` + `@huggingface/transformers`（ONNX，模型走 `/api/hf/[...path]` 代理与 `~/.ping-eng/kokoro-models` 缓存）、`idb` **不使用**（手写 Promise 封装）、`fflate`（zip 备份）。

### unique_setup_and_commands

- 手机局域网调试依赖 `next.config.mjs` 的 `allowedDevOrigins: ['192.168.110.*']`。
- 录音必须用户手势触发（iOS Safari），`WebRecorder.start()` 内需申请权限。

### gotchas_and_constraints

- `SEEK_DRIFT_THRESHOLD_MS = 300`：seek 后以实际落点修正循环边界，删除会导致单句循环漏触发。
- `idb.ts` 在 SSR/隐私模式/事务失败时**永久**切内存 Map（`useMemory`），不抛错；需要提示时用 `isMemoryFallback()`。
- 媒体文件不落 JS 内存全量读取，Blob 直接进 `blobs` store。

## AI 服务契约与 BFF（services_bff）

<!-- 迁入：kind=module, slug=services_bff, name=AI服务契约与BFF -->

### overview

`services/` 定接口与 mock/BFF 客户端实现；`app/api/*` 是 Next Route Handler 形态的 BFF；`lib/llm/` 是 BFF 侧的 LLM/ASR/TTS 适配。

### api_contract

- `SoeService.evaluate(audio, refText, 'sentence', signal?)`（契约②）
- `TtsService.generate(request, signal?)` / `getSubtitle(taskId, signal?)`（契约⑥⑦）
- `MnemonicService.generateCard/generateCardStream/generateAssociation/generateExercises/evaluateSentence`
- 通用：全部接受 `AbortSignal`，失败抛 `ApiError{code,message,detail?}`；`toApiError` 把 `AbortError` 归一为 `code:'ABORTED'`；SSE 以 `AsyncGenerator<SseEvent>` 表达，事件序 `status → token → result → done / error`。
- BFF 路由：`settings/{llm,llm-configs,soe,kokoro,local-services}`、`soe/{evaluate,health}`、`transcribe`、`transcribe/local`、`tts`、`translate`、`mnemonic`、`models`、`hf/[...path]`。
- `/api/mnemonic` 单端点多动作：`{action:'card'|'card_stream'|'association'|'exercises'|'evaluate', word, context?, meaning?, collocations?, difficulty?, sentence?, configId?}`。

### architecture_design

`contracts.ts`（接口真源）→ `mock/*`（确定性离线）→ `api/*`（同源 BFF 客户端，目前仅 `soe.ts`）；`getServices()` 恒返回 mock，`NEXT_PUBLIC_SERVICE_MODE` 仅注释预留。BFF 三件事：读 `~/.ping-eng/settings.json` → 注入密钥 → 原样透传状态码与 JSON。

### tech_stack

LangChain `ChatOpenAI`（`@langchain/openai`）为唯一 LLM 通道；provider `dashscope`(Qwen) / `mimo`，未知回退 OpenAI-compatible；DashScope 流式需 `X-DashScope-SSE: enable`，`basePath` 要剥掉 `/chat/completions`；`undici`、`https-proxy-agent` 供上游请求。

### coding_conventions

- 端点/默认模型/默认地址只写在 `lib/service-endpoints.ts`，其余地方一律 `resolveServiceUrl()` / `buildServiceUrl()`。
- 错误码集中在 `lib/llm/errors.ts` 的 `LlmError`（`API_KEY_MISSING`/`BASE_URL_MISSING`/`MODEL_NOT_CONFIGURED`/`RESPONSE_EMPTY`/`RESPONSE_FORMAT_ERROR`/`UPSTREAM_ERROR`/`REQUEST_TIMEOUT`），路由侧映射 HTTP 状态（缺失 400 / 上游 502 / 超时 504 / 取消 499）。

### gotchas_and_constraints

- 契约①③④ 已从代码移除（转写、跟读/背诵报告改走 BFF 直连与页内呈现），`types/api.ts` 仍保留 SSE 与 segments 类型 —— 别按架构文档去找 `/reports/*` 路由。
- 转发 SOE 时 multipart **文本字段必须排在 `audio` 之前**（`@fastify/multipart` 的 `req.file()` 只保证文件之前的字段可见）。
- `getAsrProviderType()` 返回 `'multimodal'` 时必须再走 WhisperX 对齐补词级时间戳，否则字幕只有段落级。
- `client/package.json` 同时装了 Vercel AI SDK（`ai`、`@ai-sdk/openai`），但代码路径用 LangChain，勿混用。

## 状态与数据模型（stores_state）

<!-- 迁入：kind=module, slug=stores_state, name=状态与数据模型 -->

### overview

`types/` 定业务与契约模型，`stores/` 用自研极简 store 把 IndexedDB 数据暴露给页面。

### architecture_design

- `stores/store.ts`：`createStore<T>(initial) → {get,set,subscribe}`，`useStore` 走 `useSyncExternalStore(subscribe, get, get)`（第三参保 SSR 安全）。
- store 清单：`material-store`（材料 + 材料集 + 种子注入 + 级联删除）、`favorite-store`、`note-store`、`vocab-store`（生词本/词条 + `updateFrequencies`）、`mnemonic-store`（助记缓存）。
- 统一模式：`createStore` 初始 `{ready:false, ...}` → 异步读写 IDB → `refresh()` 全量重读并 `set` 广播。

### data_model

- `Material{ id, name, mediaType, mediaRef, mediaFileName, mediaSizeBytes, subtitle|null, durationMs, createdAt, lastOpenedAt, collectionId? }`
- `MaterialRecord{ material, subtitleData|null }`（materials store 一条记录）
- `RECORD_KEYS`：`progress:` / `fav:` / `note:` / `train:` / `vocabbook:` / `vocabentry:` / `mnemonic:` / `collection:`
- `TrainingRecord`（五模式 + `detail` 联合）、`LearningProgress`、`Favorite`、`VocabBook/VocabEntry`、`MnemonicCard`（snake_case，对齐 LLM 输出）

### coding_conventions

- 展示型字段（颜色/进度/最近学习）不进模型，由组件按 id 派生。
- 浏览器 API 只出现在异步函数内，由 `useEffect`/事件回调触发。
- 幂等初始化用 `initPromise ??=`（`initMaterials()`）。

### gotchas_and_constraints

- `removeMaterial()` 级联：`progress:` 精确等值匹配，`fav:`/`note:` 带冒号前缀匹配，`train:` 逐条读出比 `materialId`。
- 删除材料集只解归属（成员 `collectionId` 置 `null`），不删材料。
- `assignMaterialCollection()` 有陈旧 ID 防护（目标集合已被其他标签页删除则静默不写）。
- 首次启动 `seedIfEmpty()` 注入 `data/seed.ts` 的 4 条材料（共用同一组 5 句 `seedSentences`）；清空 IDB 会重新注入。
- 禁止 zustand/Pinia。

## 后端服务（server_soe）

<!-- 迁入：kind=module, slug=server_soe, name=后端服务 -->

### overview

两条独立能力：Node Fastify 的 SOE 发音评分代理（契约②）与 Python FastAPI 的本机转写/对齐服务。均无状态、无数据库。

### architecture_design

```
server/src/index.ts            loadEnv → buildApp → listen → SIGINT/SIGTERM 优雅关闭
server/src/app.ts              Fastify 装配（cors + multipart + 统一错误出口 + /healthz）
server/src/routes/soe.route.ts POST /api/v1/soe/evaluate
server/src/services/soe/       soe-provider.ts 接口；index.ts 注册表 + resolveSoeProvider；
                               mock/azure/tencent/iflytek provider；soe-mapper.ts 归一；
                               tencent-ws-auth.ts / iflytek-auth.ts / iflytek-xml.ts；wav-pcm.ts
server/src/config/env.ts       zod 校验，各 provider 凭据齐备判定
server/align_server.py         :8765 POST /align、GET /health、GET /models
server/transcribe_server.py    :8766 POST /transcribe、GET /health（VAD + word_timestamps）
```

### api_contract

- `POST /api/v1/soe/evaluate`：multipart `refText` + `evalMode` + 可选 `provider` + 可选 `creds`(JSON) + `audio`(wav/pcm 16k mono)；响应 `{total,accuracy,fluency,integrity,words[{text,score,errorType?,phonemes[]}]}`；错误 `{code,message,detail?}`。
- `GET /healthz`：`{ok, soeProvider(默认), soeProviders(已注册集合)}`。
- Python：`POST /align`（`audio`+`text`+`language` → `words[{word,start,end}]`）、`POST /transcribe`（→ 文本 + 段落/词级时间戳）。

### tech_stack

Fastify 5 + `@fastify/cors` + `@fastify/multipart` + `ws` + `zod`，tsx 运行（`type: module`，Node ≥20）；Python 侧 `whisperx>=3.3`、`faster-whisper>=1.1`、`torch>=2`、FastAPI + uvicorn，依赖 ffmpeg。

### unique_setup_and_commands

```bash
cd server && pnpm install && cp .env.example .env
pnpm dev            # watch 模式，:8788
pnpm start          # 生产/前台运行
pnpm check          # tsc --noEmit
pnpm test           # provider 鉴权/报文/映射单测

./start.sh                                   # CPU 起转写
./start.sh --server align --device cuda      # GPU 起对齐
./start.sh --server both --device auto       # 两个都起
```

### gotchas_and_constraints

- `mock` 恒注册，其余 provider **仅在凭据齐全时注册**；请求可用 `provider` 覆盖、`creds` 提供请求级密钥（与 env 合并时请求胜出，空串视为未提供），合并后仍不齐 → 回落注册表，未注册返回 503。
- `multipart` 限制 `files:1 / fileSize:25MB / fields:5`，`bodyLimit 32MB`；413 归一为 `PAYLOAD_TOO_LARGE`。
- 上游超时/重试由 `SOE_TIMEOUT_MS`(10s) / `SOE_RETRY`(1) 控制。
- `integrity` 字段语义是完整度（已发音词/参考词比值），名字沿用契约②，勿改。
- 对齐服务**不做识别**，必须已有文本；转写服务自带词级时间戳，两者别混用职责。
- Python `.venv` 约 7.5GB，可删（`start.sh` 自动重建）。
