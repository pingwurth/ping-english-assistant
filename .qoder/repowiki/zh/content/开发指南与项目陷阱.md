# 开发指南与项目陷阱

## 1. 命令（均在 `client/` 下执行，包管理器是 pnpm）

```bash
pnpm install     # 依赖安装
pnpm dev         # next dev → localhost:3000
pnpm build       # next build
pnpm test        # vitest run（node 环境）
npx tsc --noEmit # 唯一类型检查手段，无 typecheck script
```

`server/`（Fastify SOE 代理）：`pnpm install && cp .env.example .env && pnpm start`（`:8788`），`pnpm check` 做类型检查，`pnpm test` 跑 provider/鉴权/映射单测。
`server/`（Python 语音服务）：`python3 -m venv .venv && pip install -r requirements.txt && ./start.sh`（可选 `--server align|transcribe|both --device cpu|cuda|auto`）。

**没有 ESLint / Prettier**，不要指望 lint 报错；风格以现有代码为准。

## 2. 测试边界（最容易误判的一点）

`vitest.config.mts` 只设 `environment: 'node'`，include 为 `core/**/*.test.ts` 与 `services/**/*.test.ts`（`__tests__/` 目录靠 vitest 默认 glob 命中）。测试与被测文件同目录共置：`core/subtitle/__tests__/`、`core/training/__tests__/`、`core/audio/__tests__/`、`services/mock/__tests__/`、`services/api/__tests__/`。

- **只有 core 层与 services 层的纯逻辑有测试，仓库内不存在任何 React/浏览器测试**。要验证组件行为只能靠 `pnpm dev` 手工看，或补 Node 层可测的纯函数。
- 因此 `core/` 里**不能 import DOM/React/IndexedDB**，否则测试直接挂。需要浏览器能力时放 `platform/`。
- 加新测试请沿 `@/` 别名（`tsconfig.json` 与 `vitest.config.mts` 都配了 `@/* → client/` 根）写绝对导入，与现有测试一致。

## 3. 类型检查是"软"的

`next.config.mjs` 里 `typescript.ignoreBuildErrors: true`，**`pnpm build` 不会因类型错误失败**。CI/交付前的类型保障只有手动 `npx tsc --noEmit`。改完公共类型（`types/*.ts`）务必跑一次。

## 4. 训练引擎口径纠正

架构文档 §2.5 把 `core/training/scoring.ts` 描述为「SOE 原始结果 → `ScoreReport` 评分加工」，**实际代码不是**：

- `scoring.ts` 做的是**训练会话小结**：`summarize(results, durationMs)` → `SessionSummary{ total, correctCount, accuracy(句均), durationMs, weakest(未全对句按正确率升序取前 3), totalPlays }`，`formatElapsed()` 出 `mm:ss`。
- SOE 厂商原始字段的归一在**后端** `server/src/services/soe/soe-mapper.ts`（输出统一 `SoeEvaluateResponse`），前端跟读页只做展示层加工。
- 找"评分为什么偏低/字段缺失"时，去后端 mapper 与 provider，不要在 `scoring.ts` 里找。

`puzzle.ts` 同理已演进：除文档描述的 `buildTiles/checkAnswer` 外，另有当前在用的九宫格一套（`GRID_SIZE=9` + `initGridState/selectGridWord/getGridHint/gridScore/collectDistractorWords`）。

## 5. 字幕解析（`core/subtitle/`）

`srt.ts` / `lrc.ts` / `bilingual.ts` / `timestamp.ts` / `errors.ts` / `index.ts`，零依赖。入口只有 `parseSubtitle(text, format?, knownDurationMs?)` 与 `exportSrt(sentences)`。要点：

- 双语判定 `isCJK(line)`，两行上英下中/上中下英互为反序，单行只填 `textEn`，两行同类或多行按语言分组合合并并**保留原文换行**（`'\n'` 连接，导出 SRT 可原样回写，渲染侧配 `whitespace-pre-line`）。
- 含 `textZh` 句占比 >30% → `isBilingual = true`。
- LRC 无结束时间：`endMs` 取下一句 `startMs`，末句取 `totalDurationMs`（因此需要传 `knownDurationMs`）。
- `words` 切分按 `/\s+/` 并 `stripWordPunctuation` 剥离首尾标点，**保留撇号**（`don't` 是一个词）。
- 解析失败抛带行号的 `SubtitleParseError`，导入页就地提示——这个错误信息是 UX 的一部分，别吞掉。

## 6. 已知陷阱清单

| 陷阱 | 说明 |
|------|------|
| `components/study-app.tsx` 是唯一路由表 | 17 条客户端路由集中于此；`next dev` 会重写 `client/AGENTS.md` 的 Next 规则块，提交时保留该自动块 |
| seek 漂移补偿不可删 | `SEEK_DRIFT_THRESHOLD_MS = 300`（`platform/html-player.ts`），删掉单句循环会漏触发 |
| `LOOP_TOLERANCE_MS = 120` | 单句循环边界容差，与上面配套，别单独调小 |
| `getServices()` 恒返回 mock | 真实服务切换靠 `NEXT_PUBLIC_SERVICE_MODE`，目前仅注释预留 |
| BFF multipart 字段顺序 | 文本字段必须在 `audio` 之前追加，否则 Fastify 侧读不到 `refText` |
| `records` store 前缀删除 | `progress:` 必须精确匹配，前缀匹配会误删互为前缀的材料（`m-1` / `m-10`） |
| IndexedDB 静默降级 | `idb.ts` 打开失败/`onblocked`/事务抛错后**永久**切内存 Map，数据不落盘也不报错（`isMemoryFallback()`） |
| `~/.ping-eng/settings.json` 明文密钥 | 单条 `?id=` 查询有意返回明文（仅本机），列表接口才脱敏 |
| `page-prototype/` 是独立沙箱 | 有自己的 `package.json`/`node_modules`，改动不影响 `client/` |
| 种子数据自动注入 | 首次启动且 `materials` 为空时注入 `data/seed.ts`（4 条材料共用同一组 5 句）；清空 IDB 会重新触发 |
| `allowedDevOrigins: ['192.168.110.*']` | 手机局域网访问 H5 必需，换网段要同步改 |
| LangChain 与 AI SDK 并存 | `package.json` 同时有 `ai`/`@ai-sdk/openai` 与 `@langchain/*`，实际走 LangChain，勿混用 |
| 供应商端点只能集中一处 | 所有 endpoint/默认模型/默认地址只在 `lib/service-endpoints.ts`，别在调用侧硬编码 |

## 7. 文档纪律

- 代码注释、文档、提交信息一律**中文（zh-CN）**。
- `docs/系统架构设计.md` 是契约与数据模型的规范来源；新增 API/模型时先改文档再落代码，并在代码注释里以「真源：docs/…§X」回链。
- 描述"当前实现"以代码为准，描述"契约/模型/决策理由"以架构文档为准；两者冲突先记进知识库再修文档，不要默默改代码。
- `docs/` 下还有各功能的独立方案文档（生词本、生词训练、发音评分技术选型、Qwen 识别/生成接入、原型设计、技术选型），动相应模块前先读对应篇。
