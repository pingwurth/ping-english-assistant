# Plan: Implement Persistent Caching for Kokoro TTS Model

## Problem Analysis

**Root Cause:**
The Kokoro TTS model (~90MB ONNX) is downloaded fresh every time the user navigates to the TTS page or refreshes the browser. The current implementation uses a module-level variable (`ttsPromise`) that resets on page refresh, forcing a complete re-download.

**Current Behavior:**
- Model downloads from HuggingFace every time `getKokoroTts()` is called after page refresh
- Voice files ARE cached via `caches.open("kokoro-voices")` (implemented in kokoro-js library)
- Main ONNX model is NOT properly cached in browser storage
- Module-level singleton (`ttsPromise`) only persists within a single page session

**Why It Happens:**
1. `kokoro-js` library's `from_pretrained()` uses `@huggingface/transformers` which should support IndexedDB caching, but caching is not working correctly in this browser environment
2. The model files are downloaded via HTTP but not persisted to browser storage
3. No fallback caching mechanism is implemented

## Solution Strategy

Implement a multi-layer caching strategy:
1. **Primary:** Use browser Cache Storage API to cache ONNX model files
2. **Fallback:** Use IndexedDB for model metadata and configuration
3. **Verification:** Check cache before downloading, with cache invalidation logic

#### 2.1 Add Cache Storage Wrapper
```typescript
const MODEL_CACHE_NAME = 'kokoro-model-cache'
const MODEL_ID = 'onnx-community/Kokoro-82M-v1.0-ONNX'

async function getCachedModel(modelId: string): Promise<Response | null> {
  try {
    const cache = await caches.open(MODEL_CACHE_NAME)
    const response = await cache.match(modelId)
    return response || null
  } catch (e) {
    console.warn('Cache read failed:', e)
    return null
  }
}

async function cacheModel(modelId: string, response: Response): Promise<void> {
  try {
    const cache = await caches.open(MODEL_CACHE_NAME)
    await cache.put(modelId, response.clone())
  } catch (e) {
    console.warn('Cache write failed:', e)
  }
}
```

Update `getKokoroTts()` to check cache first:
```typescript
export function getKokoroTts(): Promise<KokoroTTS> {
  if (!ttsPromise) {
    emitLoad({ phase: 'downloading' })
    ttsPromise = (async () => {
      const { KokoroTTS } = await import('kokoro-js')
      
      // Check cache first
      const cached = await getCachedModel(MODEL_ID)
      if (cached) {
        // Use cached model
        emitLoad({ phase: 'initializing' })
        // ... load from cache
      } else {
        // Download and cache
        const tts = await KokoroTTS.from_pretrained(MODEL_ID, {
          dtype: 'q8',
          device: 'wasm',
          progress_callback: (p) => {
            if (p && p.status === 'progress') {
              emitLoad({ phase: 'downloading', file: p.file, percent: p.progress })
            }
          },
        })
        // Cache the model files
        await cacheModelFiles(MODEL_ID)
        return tts
      }
    })().catch((err) => {
      ttsPromise = null
      throw err
    })
  }
  return ttsPromise
}
```

### Phase 3: Implement Model File Extraction
Since `kokoro-js` doesn't expose the raw model files, we need to:
1. Intercept the download requests
2. Cache the responses
3. Serve from cache on subsequent loads

**Approach:** Use Service Worker or fetch interceptor to cache model files

#### 3.1 Create Service Worker (Optional)
**File:** `client/public/sw.js`
```javascript
const CACHE_NAME = 'kokoro-model-v1'
const MODEL_URLS = [
  'https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX/resolve/main/onnx/model_quantized.onnx',
  // Add other model files as needed
]

self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url)
  
  if (url.hostname === 'huggingface.co' && url.pathname.includes('Kokoro-82M')) {
    event.respondWith(
      caches.match(event.request).then((cached) => {
        if (cached) return cached
        
        return fetch(event.request).then((response) => {
          const responseClone = response.clone()
          caches.open(CACHE_NAME).then((cache) => {
            cache.put(event.request, responseClone)
          })
          return response
        })
      })
    )
  }
})
```

### Phase 4: Implement IndexedDB Fallback
For browsers that don't support Cache Storage or for additional metadata:

#### 4.1 Create IndexedDB Manager
**File:** `client/lib/model-cache.ts`
```typescript
const DB_NAME = 'kokoro-model-db'
const DB_VERSION = 1
const STORE_NAME = 'models'

class ModelCacheDB {
  private db: IDBDatabase | null = null
  
  async open(): Promise<void> {
    return new Promise((resolve, reject) => {
      const request = indexedDB.open(DB_NAME, DB_VERSION)
      request.onerror = () => reject(request.error)
      request.onsuccess = () => {
        this.db = request.result
        resolve()
      }
      request.onupgradeneeded = (event) => {
        const db = (event.target as IDBOpenDBRequest).result
        if (!db.objectStoreNames.contains(STORE_NAME)) {
          db.createObjectStore(STORE_NAME, { keyPath: 'id' })
        }
      }
    })
  }
  
  async get(key: string): Promise<any> {
    return new Promise((resolve, reject) => {
      const transaction = this.db!.transaction(STORE_NAME, 'readonly')
      const store = transaction.objectStore(STORE_NAME)
      const request = store.get(key)
      request.onerror = () => reject(request.error)
      request.onsuccess = () => resolve(request.result)
    })
  }
  
  async put(key: string, value: any): Promise<void> {
    return new Promise((resolve, reject) => {
      const transaction = this.db!.transaction(STORE_NAME, 'readwrite')
      const store = transaction.objectStore(STORE_NAME)
      const request = store.put({ id: key, ...value })
      request.onerror = () => reject(request.error)
      request.onsuccess = () => resolve()
    })
  }
}

export const modelCacheDB = new ModelCacheDB()
```

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Browser cache limits | Model too large for cache | Use IndexedDB for large files |
| Cache corruption | Model won't load | Implement cache validation |
| Service Worker issues | Caching fails | Fallback to direct caching |
| Storage quota exceeded | Can't cache model | Implement cache size limits |
