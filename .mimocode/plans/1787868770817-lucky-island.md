# Plan: Multi-Model Config List UI for Settings Page

## Problem

The current `ModelConfigSection` in `settings.tsx` renders a single inline form for one LLM provider config (ASR + TTS). Users cannot configure multiple providers simultaneously (e.g., Qwen for ASR + MiMo for TTS + a different LLM). The UI lacks list view, add/edit dialog, and per-item CRUD operations.

## Design

### Data Model

Extend `~/.ping-eng/settings.json` to store an array of model configs:

```json
{
  "llm": { ... },              // kept for backward compat (mirrors the default config)
  "llmConfigs": [              // NEW: array of all configs
    {
      "id": "cfg_1712345678_abc",
      "name": "Qwen ASR+TTS",
      "provider": "qwen",
      "baseUrl": "https://...",
      "apiKey": "sk-...",
      "asrModel": "...",
      "asrEndpoint": "...",
      "ttsModel": "...",
      "ttsEndpoint": "..."
    }
  ],
  "defaultLlmConfigId": "cfg_1712345678_abc"
}
```

- `id`: auto-generated unique string (`cfg_${Date.now()}_${rand4}`)
- `name`: user-editable label shown in the list (auto-suggested from provider name)
- `defaultLlmConfigId`: which config is the default (used by TTS/transcribe routes)
- The legacy `llm` field mirrors the default config for backward compat

### WhisperX/faster-whisper → New Tab

Move WhisperX and faster-whisper URL config out of model config into a new **"本地服务"** tab (5th tab). This is a global setting, not per-model.

### API Surface

New route: `client/app/api/settings/llm-configs/route.ts`

| Method | Purpose |
|--------|---------|
| GET | Return `{ configs: [...], defaultId }` (API keys masked) |
| POST | Add new config → returns `{ id }` |
| PUT | Update config by `{ id, ...fields }` |
| DELETE | Delete config by `{ id }` |

Separate route: `client/app/api/settings/local-services/route.ts`

| Method | Purpose |
|--------|---------|
| GET | Return `{ whisperAlignUrl, whisperTranscribeUrl }` |
| PUT | Update local service URLs |

When the default config changes, sync it to the legacy `llm` field so existing consumers (tts.tsx, transcribe routes) continue working unchanged.

# Plan: Adapt tts.tsx & transcribe-shared.tsx for Multi-Model Selection

## Problem

`tts.tsx` and `transcribe-shared.tsx` currently read only the single default config from `/api/settings/llm`. With multi-model support in place, users need to select from ALL configured models (not just the default).

## Current Data Flow

### tts.tsx
- Fetches `/api/settings/llm` → reads `configured`, `ttsModel`, `ttsVoices`
- Dropdown shows: `cloud` (ttsModel name) vs `kokoro` (local), or `kokoro` + "添加模型"
- On generate: calls `POST /api/tts` with `{ text, voice, speed }` — server reads `readLlmSettings()` (default config)

### transcribe-shared.tsx
- `checkLlmConfigured()` fetches `/api/settings/llm` → checks `configured`
- On transcribe: calls `POST /api/transcribe` — server reads `readLlmSettings()` (default config)
- No model selector UI — just "调用大模型" button

## Design

### TTS page model dropdown

Replace the binary `cloud`/`kokoro` dropdown with a multi-option selector:

```
模型：
  [qwen-audio-3.0-tts-plus · Qwen ASR+TTS]   ← config 1 (has ttsModel)
  [mimo-tts-v2 · MiMo 本地]                   ← config 2 (has ttsModel)
  [kokoro · 本地离线]                           ← always present
  [＋ 添加模型]                                ← navigate to settings
```

- Fetch `/api/settings/llm-configs` instead of `/api/settings/llm`
- Filter configs where `ttsModel` is truthy → these are cloud TTS options
- Each option's value = config `id` (or `'kokoro'` for local, `'__add_model__'` for CTA)
- Voice list: derive from `getTtsVoices()` logic based on selected config's provider
- On generate: pass `{ configId }` to `/api/tts`

### Transcribe page model selection

Add an ASR model selector to the "调用大模型" method section:

- Fetch `/api/settings/llm-configs` → filter configs where `asrModel` is truthy
- Show dropdown of available ASR configs (name + model)
- On transcribe: pass `{ configId }` to `/api/transcribe`

### API route changes

Add `readLlmConfigById(id)` to `server-settings.ts`.

Update `/api/tts` POST: accept optional `configId` param. If provided, use `readLlmConfigById()`; otherwise fall back to `readLlmSettings()`.

Update `/api/transcribe` POST: same pattern.

`/api/settings/llm-configs` GET: return voice lists per config (add `ttsVoices` field to each config response).

## Files to Modify

| File | Change |
|------|--------|
| `client/lib/server-settings.ts` | Add `readLlmConfigById(id)` |
| `client/app/api/tts/route.ts` | Accept `configId` param, use it to resolve settings |
| `client/app/api/transcribe/route.ts` | Accept `configId` param, use it to resolve settings |
| `client/app/api/settings/llm-configs/route.ts` | Return `ttsVoices` per config in GET response |
| `client/components/pages/tts.tsx` | Fetch all configs, populate multi-option dropdown |
| `client/components/shared/transcribe-shared.tsx` | Add ASR config selector, pass `configId` |

## Implementation Steps

### T1: Add readLlmConfigById to server-settings.ts
- Add function: `readLlmConfigById(id: string): Promise<LlmSettings | null>`
- Reads `llmConfigs` array, finds by id, returns as LlmSettings (strips id/name)
- Acceptance: returns correct config by id, null if not found

### T2: Update API routes to accept configId
- `/api/tts` POST: extract `configId` from body, resolve via `readLlmConfigById()` or fallback
- `/api/transcribe` POST: same pattern
- `/api/settings/llm-configs` GET: include `ttsVoices` in each config response
- Acceptance: API works with and without configId

### T3: Adapt tts.tsx
- Replace `fetch('/api/settings/llm')` with `fetch('/api/settings/llm-configs')`
- Build model options from configs with `ttsModel` + kokoro + "添加模型"
- Track `selectedConfigId` state (default to defaultId)
- Derive voice list from selected config's provider
- Pass `configId` in POST body to `/api/tts`
- Acceptance: dropdown shows all TTS configs, voice list updates on switch, generation works

### T4: Adapt transcribe-shared.tsx
- Fetch `/api/settings/llm-configs` in `useTranscribe` hook
- Add ASR config selector UI in `MethodHint` for `method === 'model'`
- Pass `configId` in transcribe POST
- Acceptance: ASR model selector visible, transcription works with selected config
