# Fix: 云端 TTS 404 — buildTtsUrl 忽略 ttsEndpoint 配置

## Root Cause

`client/app/api/tts/route.ts:40-44` 的 `buildTtsUrl()` 硬编码 DashScope 原生路径，忽略 `ttsEndpoint`。
用户的 MiMo 配置 (`ttsEndpoint: "/chat/completions`) 从未被使用。

## MiMo TTS API（已 curl 验证通过）

```
POST https://token-plan-cn.xiaomimimo.com/v1/chat/completions
Authorization: Bearer <apiKey>

{
  "model": "mimo-v2.5-tts",
  "messages": [{ "role": "assistant", "content": "要合成的文本" }],
  "modalities": ["text", "audio"],
  "audio": { "voice": "Mia", "format": "wav" }
}
```

响应: `{ choices: [{ message: { audio: { data: "<base64 WAV>" } } }] }`

可用音色: `mimo_default`, `冰糖`, `茉莉`, `苏打`, `白桦`, `Mia`, `Chloe`, `Milo`, `Dean`

## 落地方案：三层分支

### 第一层：Provider 检测

在 `route.ts` 顶部加一个检测函数（参照 `transcribe/route.ts` 的 `isAudioChatModel`）：

```ts
type TtsProvider = 'mimo' | 'dashscope'

function detectTtsProvider(settings: LlmSettings): TtsProvider {
  if (settings.ttsEndpoint?.includes('chat/completions')) return 'mimo'
  if (settings.provider === 'mimo') return 'mimo'
  return 'dashscope'
}
```

### 第二层：URL + 请求体 + 响应解析 各自独立

| 层面 | DashScope | MiMo |
|---|---|---|
| **URL** | `buildDashScopeTtsUrl(baseUrl)` → 去掉 `/v1` 后缀 + `/api/v1/services/audio/tts/SpeechSynthesizer` | `baseUrl + ttsEndpoint` → `https://...xiaomimimo.com/v1/chat/completions` |
| **请求体** | `{ model, input: { text, voice, format:"wav", sample_rate:24000, rate, language_hints:["en"] } }` | `{ model, messages:[{role:"assistant", content:text}], modalities:["text","audio"], audio:{voice, format:"wav"} }` |
| **音频提取** | `result.output.audio.url` → fetch 下载 → Buffer | `result.choices[0].message.audio.data` → base64 decode → Buffer |
| **音色** | `longanlingxin`, `longanlufeng` (双语) | `Mia`, `Chloe`, `Milo`, `Dean` 等 (英文) |

### 第三层：前端音色列表

**方案**: `/api/settings/llm` GET 响应新增 `ttsVoices` 字段，后端根据 provider 返回对应音色列表。
前端 `tts.tsx` 从 settings 读取 `ttsVoices` 替代硬编码的 `CLOUD_VOICES`。

## 具体修改

### 文件 1: `client/app/api/tts/route.ts`（核心修复）

1. 新增 `detectTtsProvider()` 函数
2. 保留 `buildTtsUrl()` 给 DashScope 用，重命名为 `buildDashScopeTtsUrl()`
3. 新增 `generateTtsMimo()` 函数 — 构造 MiMo 请求、解析响应、返回 Buffer
4. 新增 `generateTtsDashScope()` 函数 — 从现有 POST handler 抽取
5. POST handler 中按 provider 分支调用
6. 错误处理：MiMo 的错误格式为 `{ error: { code, message } }`，DashScope 为 `{ message }` 或 `{ error.message }`

### 文件 2: `client/app/api/settings/llm/route.ts`

1. GET handler 新增 `ttsVoices` 字段
2. 根据 `settings.ttsEndpoint` 或 `settings.provider` 返回对应音色列表

```ts
const ttsVoices = (settings.ttsEndpoint?.includes('chat/completions') || settings.provider === 'mimo')
  ? [
      { id: 'Mia', label: 'Mia · Female' },
      { id: 'Chloe', label: 'Chloe · Female' },
      { id: 'Milo', label: 'Milo · Male' },
      { id: 'Dean', label: 'Dean · Male' },
    ]
  : [
      { id: 'longanlingxin', label: 'Lingxin · Female (双语)' },
      { id: 'longanlufeng', label: 'Lufeng · Male (双语)' },
    ]
```

### 文件 3: `client/components/pages/tts.tsx`

1. 新增 state: `const [cloudVoices, setCloudVoices] = useState(CLOUD_VOICES)`
2. 从 `/api/settings/llm` 响应中读取 `ttsVoices` 并 set
3. `voices` 计算改为: `engine === 'kokoro' ? KOKORO_VOICE_LIST : cloudVoices`
4. 移除顶部硬编码的 `CLOUD_VOICES` 常量（或保留作为 fallback）
