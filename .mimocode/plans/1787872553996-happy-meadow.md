# Plan: Click "调用大模型" button → show model config list dialog

## Problem

Clicking the "调用大模型" (model) button in the transcribe page's MethodSelector currently only sets the method to `'model'`. The user expects a dialog to pop up showing the full model configuration list from settings, with CRUD capabilities (add/edit/delete/set-default).

## Design

### Approach

Extract `ModelConfigListSection` + `ModelConfigDialog` from `settings.tsx` into a shared file, wrap them in a `Dialog`, and wire the "调用大模型" button to open this dialog.

### Changes

#### 1. Create `client/components/shared/model-config-list-dialog.tsx`

New shared component. Move these from `settings.tsx`:
- `LlmConfigItem` interface (line 267)
- `ModelConfigDialog` function (line 282–586)
- `ModelConfigListSection` function (line 590–728)

Export `ModelConfigListDialog` — a wrapper that:
- Renders `ModelConfigListSection` inside a `Dialog` (using existing `client/components/ui/dialog.tsx`)
- Props: `open: boolean`, `onOpenChange: (open: boolean) => void`, `onConfigsChanged?: () => void`, `onSaved?: () => void`
- `onConfigsChanged` is called after any CRUD operation (add/edit/delete/set-default) so the caller can refresh its local config cache
- `onSaved` is forwarded to the nested `ModelConfigDialog` — called after a config is added/edited. Used by `useTranscribe` to close the dialog and auto-retry transcription when the user was prompted to add a config during `start()`

#### 2. Update `client/components/pages/settings.tsx`

- Remove `LlmConfigItem`, `ModelConfigDialog`, `ModelConfigListSection` (now in shared file)
- Import `ModelConfigListSection` from the new shared file
- No behavior change

#### 3. Update `client/components/shared/transcribe-shared.tsx`

- Add `onOpenModelConfig?: () => void` prop to `MethodSelector`
- When `method === 'model'` button is clicked, call both `setMethod('model')` and `onOpenModelConfig?.()`
- Extract the asrConfigs fetch logic into a `loadAsrConfigs` function (currently inline in `useEffect`), expose it from `useTranscribe` as `refreshConfigs` so callers can re-fetch after dialog changes
- Rename `showLlmSettings` → `showModelConfig` and `handleLlmSettingsSaved` → `handleModelConfigSaved` for clarity (same logic: auto-opens dialog when `start()` has no ASR configs, retries transcription on save)

#### 4. Update `client/components/pages/transcribe.tsx`

- Replace `LlmSettingsDialog` import with `ModelConfigListDialog` from the new shared file
- Use `showModelConfig` / `setShowModelConfig` from `useTranscribe()` (renamed from `showLlmSettings`) for dialog visibility — serves both button-click and auto-open-during-start
- Destructure `refreshConfigs`, `handleModelConfigSaved` from `useTranscribe()`
- Pass `onOpenModelConfig={() => setShowModelConfig(true)}` to `MethodSelector`
- Pass `onConfigureLlm={() => setShowModelConfig(true)}` to `MethodHint`
- Render `<ModelConfigListDialog open={showModelConfig} onOpenChange={setShowModelConfig} onConfigsChanged={refreshConfigs} onSaved={handleModelConfigSaved} />`
- Remove `LlmSettingsDialog` entirely

#### 5. Update `client/components/shared/ai-transcribe-dialog.tsx`

Same pattern as transcribe.tsx:
- Replace `LlmSettingsDialog` import with `ModelConfigListDialog`
- Use `showModelConfig` / `setShowModelConfig` from `useTranscribe()` for dialog visibility
- Destructure `refreshConfigs`, `handleModelConfigSaved` from `useTranscribe()`
- Pass `onOpenModelConfig={() => setShowModelConfig(true)}` to `MethodSelector`
- Render `ModelConfigListDialog` with `onConfigsChanged={refreshConfigs}` and `onSaved={handleModelConfigSaved}`
- Remove `LlmSettingsDialog`

#### 6. Keep `llm-settings-dialog.tsx` as-is (no delete)

Legacy dialog — not deleted to avoid breaking other potential imports. It's simply no longer used by the transcribe flow.
